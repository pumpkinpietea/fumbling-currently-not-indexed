# Design

Add safe upstream error classification to existing stream/HTTP failure handling, with phase/status but no arbitrary upstream messages. Keep terminal-event failure semantics and zero retries. Persist model text privately under dated evidence keys capped at64KiB; protect credentials separately.

For schema4, accept an explicit editions array and enforce conservative geographic/topic bounds, while allowing a general Indonesia item with incidental AI context to exclude tech. The skeptical reviewer independently checks actual membership and shared technology coverage. Old event shapes retain exact schemas1–3 rendering/validation.

Normalize numeric punctuation only for explicitly declared new events. ANTARA uses explicit id-ID evidence formatting, while EN/JP outputs use canonical comma grouping/dot decimals. Compare canonical values without changing source quotes or hashes. Use original grouping in quotes and normalized values in fact text.

Wrap daily execution in phase-aware diagnostics, preserve failed-date locks, and publish redacted failed/no_news status to the existing private bundles prefix only for production. The consumer checks status only if no valid publication bundle exists. Trials never write production status/bundles.

Correct the retained operator candidate for October14, re-review once under the authoritative rotating session/global lease, inspect facts and render the actual nonempty topics. Commit recovered content with the code fix through protected CI; roll out immutable validated main, verify live pages, and record private recovery history once. No blind rerun or overwrite of the original failed marker.
